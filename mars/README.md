# Освоение Марса — агент v1

Рабочая реализация интерактивного агента для **Python 3.11**, протокол v3.

## Файлы

- `solution.py` — решение для отправки в проверяющую систему.
- `starter.py` — исходный шаблон из пакета участника, сохранён без изменений.
- `simulate.py` — точный локальный симулятор и проверка десяти историй.
- `test_solution.py` — проверки легальности заявок и интерактивного протокола.
- `benchmark_replay.py` — диагностический эксперимент против зафиксированных заявок соперника.
- `tests/` — десять открытых тестовых карт.
- `histories/` — десять историй self-play.
- `SOURCE_NOTES.md` — извлечённые из пакета правила и замечания по версии условия.

## Алгоритм

На каждом ходу агент:

1. Восстанавливает доступные клетки по собственной станции и старым роботам.
2. Строит динамические расстояния от фронтиров соперников и статические расстояния от станций.
3. Для каждой доступной клетки оценивает предельный доход от добавления ещё одного робота:

   `delta = income(x + 1, y) - income(x, y)`

   где `x` — наши роботы, `y` — роботы соперников в клетке.
4. Учитывает оставшееся число ходов, риск будущего занятия клетки соперником и ценность открытия соседних клеток.
5. Жадно распределяет целочисленный бюджет между клетками по убыванию ожидаемой предельной выгоды.
6. Не размещает роботов, если ожидаемая выгода следующего робота неположительна.

Доходы и запасы представлены целыми числами в масштабе `10**d`, где `d` — максимальное число знаков после точки в `R0`, `a`, `b`. Промежуточного округления нет.

## Протокол

- Сразу после начального блока выводится первая заявка.
- На каждом ходу выводится ровно одна строка, затем выполняется flush.
- Затем читаются ровно `N-1` строк заявок соперников. Пустая строка — полноценная заявка-пропуск.
- Затем читается одна строка запасов всех игроков.
- Даже после последнего собственного хода нужно прочитать заявки соперников и итоговые запасы.
- В stdout нет диагностических сообщений.

## Запуск

Из корня репозитория:

```bash
python3.11 mars/solution.py
```

Локальные проверки:

```bash
python -m unittest -v mars.test_solution
python mars/simulate.py
python mars/benchmark_replay.py
```

## Ограничения интерпретации результатов

`histories/` — self-play записи. Проверка `simulate.py` воспроизводит их точную экономику и подтверждает корректность локального симулятора. `benchmark_replay.py` повторяет записанные действия соперника без адаптации к изменившемуся состоянию; при нехватке ресурса заявка обрезается. Поэтому это только диагностический эксперимент, а не официальный результат или точная симуляция скрытого бота.

## Замечание о версии условия

В загруженном `statement.md` формула оценки указана как `Q = sum(R_k / T_k)`, `S = 10 Q / B`. На скриншотах страницы задачи в чате показана другая формула: нормировка `min(1, N_k R_k / U_k)` и максимум 12 баллов. Игровая механика и протокол в доступных материалах совпадают, но перед финальной отправкой нужно сверить актуальную формулу оценки на платформе.
