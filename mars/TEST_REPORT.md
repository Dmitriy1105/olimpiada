# Отчёт тестирования — «Освоение Марса», v4

## 1. Основание

v4 создана от проверенной реализации v1, а не от v3. По сообщениям пользователя официальные результаты предыдущих вариантов:
- v1: 6,24 (округлённое отображение);
- v2: 6,236;
- v3: 6,122.

v3 отклонена. Цель v4 — проверить индивидуальную адаптацию к наблюдаемому поведению соперников, не меняя базовую экономическую стратегию v1.

## 2. Изменения алгоритма

- Сохранены fixed-point ресурсы, расчёт предельного дохода, оценка расширения, heap и протокол v3 из v1.
- Для каждого соперника отдельно оценивается вероятность будущего размещения в каждой клетке.
- Признаки: динамическая достижимость от сети соперника, расстояние от его станции относительно нашей, текущая доступность клетки.
- Онлайн-статистика соперника: число допустимых размещённых роботов, число размещений на нашей доступной границе, EMA доли потраченного на ход бюджета.
- Для нескольких соперников ожидаемый доход вычисляется по всем комбинациям Bernoulli-событий; для 4 игроков это максимум 8 исходов на клетку.
- В прогнозе не используются действия соперников текущего хода, которые ещё не получены.

## 3. Тесты

GitHub Actions на Python 3.11 запускает:
1. Unit и интерактивные протокольные тесты.
2. Точное воспроизведение 10 историй.
3. Диагностический replay v4.
4. Парный replay v1 против v4.
5. Отдельный unit-тест четырёхпользовательской модели и проверки адаптации после наблюдаемого действия.

Статус GitHub Actions для текущего коммита следует считать окончательным только после завершения workflow.

## 4. Интерпретация benchmark

Даже парный replay не является официальной оценкой: в нём используются 10 открытых двухпользовательских карт и фиксированные действия соперника. При изменении нашего поведения соперник не перестраивает стратегию; его заявку приходится ограничивать изменившимся бюджетом. Это диагностическая оценка чувствительности, а не прогноз турнирного балла.

## 5. Критерий принятия v4

v4 не заменяет v1 автоматически. Для подачи на платформу сначала проверяются CI и локальный парный replay; затем пользователь сообщает официальный результат. v4 считается улучшением только если официальный результат выше 6,24. Иначе v1 остаётся лучшей подтверждённой версией.
